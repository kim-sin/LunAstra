# LunAstra 4.1.0 — model-scope.1

A focused model-scope/lifetime addition to 4.0 stateflow. It does not replace fixed-seven or remove the continuous local research machinery.

Newly injected protocol is scoped to an accepted Luna activation/turn/role and explicitly inactive after leaving that scope or disabling/unregistering hooks. All new non-Luna/unknown-model events exit before task imports/state/prompt work. One shared classifier serves both gates. Bare `gpt-reserve` is deliberately UNKNOWN until a reliable Luna-only discriminator is demonstrated; explicit versioned Luna variants remain active.

Includes bounded opt-in model-gate capture, separated CHECK layers, optional targeted isolated home, and explicit unregister warnings that old conversation context is not retracted. State-v3, state-v4, previous releases, project files, account/model settings and unrelated hooks are preserved. Registration and host approval remain operator actions.

Automated model-gate/no-side-effect/lifetime/trace/installer regressions supplement the existing suite. Synthetic payloads are not actual Desktop model selection, and prompt text is not a hard revocation API. The original contamination cause is unconfirmed because its live model payload is missing. Actual host acceptance remains in [MODEL_SCOPE.md](MODEL_SCOPE.md); do not declare it passed from software tests.

Install from a fresh extracted folder only when ready. Do not purge state or kill workers to force an update. A mixed-home installation does not prove Desktop/IDE routing and does not copy credentials. Existing pre-4.1 contaminated conversations should be replaced by clean non-Luna conversations, not rewritten with fabricated runtime claims.
