# Resume a caller-authorized chain
Implement advance(stages, completed, run), where stages is an ordered sequence of distinct (id, identity) pairs. completed maps id to {'identity':..., 'result':...}. Do not mutate inputs. Reuse only matching identities. Call run(id) for missing/stale stages in order; successful run returns {'ok': True, 'value': ...}. The first result not explicitly ok=True stops later dependent stages; return {'completed': new_mapping, 'failed': id_or_None}. Retain useful completed records; overwrite that stage's record only on success. Reject duplicate stage ids. No new scheduling infrastructure.
